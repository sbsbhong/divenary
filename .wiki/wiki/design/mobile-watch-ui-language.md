## 요약

`diving-app`의 모바일과 watchOS UI는 **iOS grouped base + dive instrument accent**를 공통 방향으로 삼는다. 워치 기록 화면은 2026-10-23 리디자인 'Plumb · 측심'부터 상태 띠·depth gauge·안내 칩이 고정된 하나의 계기이고, 다이버가 화면을 넘기면 오른쪽 값 열만 바뀐다. 모바일 cloud 상태는 backend가 없을 때 숨기고, 실제 상태가 생긴 뒤에만 low-chroma badge를 사용한다. Safety stop 권장 상태와 future mandatory/decompression 상태는 색상 severity를 분리한다.

2026-10-22 개편부터 화면 문구는 다이버가 자연스럽게 읽는 말로 쓰고 개발자·시스템 용어를 화면에 내보내지 않으며, 개념 하나에는 용어 하나만 쓴다. 로딩 표시는 naver-ad-bidder 전략을 따라 1초 전에는 아무것도 보이지 않고, 1초부터 실제 모양의 정적 스켈레톤이나 spinner, 4초부터 짧은 문구, 10초부터 재시도를 보인다. 워치 실제 기록은 동작 버튼 한 번 누르기와 크라운 회전으로 화면을 넘기고, 다음 누르기가 무엇을 하는지 한 줄 안내 chip으로 알린다.

워치의 색은 한 색에 한 의미만 준다: 검은 바탕, 흰 데이터(큰 숫자), 회색 라벨, 수심에 고정된 남색 물기둥, 누르기·선택에만 쓰는 파랑, 권장 스탑에만 쓰는 앰버. 모양은 캡슐·원이 누를 수 있는 것, 둥근 사각형이 정보다. 모션은 물속에서 차분하고(자동 변화는 크로스페이드, 다이버가 넘길 때만 이동, 숫자는 굴리지 않음) 물 밖에서 축하한다(저장 뒤 그래프가 그려지고 실제 로고가 선을 따라감). 애플 watchOS 문법은 따르되 애플 '수심' 앱 하나를 강하게 연상시키는 요소는 쓰지 않고, 가오리는 실제 로고만 쓴다.

## 현재 상태

이 결정은 `DESIGN.md`의 Apple-inspired token과 사용자의 UI 피드백을 모바일 앱과 watchOS 앱에 맞게 해석한 것이다. `DESIGN.md`는 Apple 웹/마케팅 page의 full-bleed tile 언어를 포함하지만, 모바일 앱과 watchOS 앱에는 그대로 복사하지 않는다.

모바일 앱의 기준은 다음과 같다.

- iOS `Settings`, `Health`, `Fitness`처럼 grouped list와 조용한 card surface를 기본으로 한다.
- 화면마다 핵심 시각 요소는 하나만 둔다.
- 다이빙 도메인감은 `DepthProfile`, 주요 수심, 시간, 상태 표시처럼 계기성 정보에만 둔다.
- 정보 구조는 `screen header → primary summary group → secondary grouped rows → optional primary action` 순서를 따른다.

watchOS 앱의 기준은 다음과 같다.

- iPhone의 흰 grouped list를 그대로 옮기지 않는다.
- watchOS에서는 black canvas, compact rounded surface, 짧은 label/value, 큰 recording metric 하나를 중심으로 한다.
- recording 화면은 현재 수심, 경과 시간, 상태처럼 즉시 읽어야 하는 정보 하나를 우선한다.
- recording 화면은 위 상태 띠, 왼쪽 depth gauge(46pt), 오른쪽 값 열, 아래 안내 칩이 고정된 하나의 계기다. 화면을 넘겨도 값 열만 바뀌고, 수심/시간 값을 card 안에 반복 배치하지 않는다.
- Home은 프리다이빙·스쿠버 시작 카드 두 개를 주 요소로 두고, 모바일 계획 선택은 다이빙 계획 행으로, Demo는 아래쪽 보조 행으로 보낸다. 맨 아래에는 실제 로고와 비인증 문장을 둔다.
- 저장 요약은 최대 수심 → 다이빙 시간 → 수심 그래프 → `워치에 저장됨` 순서이고, saved session과 detail 화면은 compact summary, mini profile, 필요한 action 정도만 둔다.

## 상세

### 공통 원칙

- 보더와 장식으로 구분하지 않고 배경, 간격, 타이포 위계로 구분한다.
- 카드 안에 카드를 넣지 않는다.
- 큰 badge나 pill을 화면마다 반복하지 않는다.
- status badge는 낮은 채도와 얇은 강조만 가진 chip이어야 하며, primary-filled button처럼 보이면 안 된다.
- 40m 초과 unsupported-depth marker는 낮은 채도의 review warning으로 표시하고, critical alarm이나 수중 행동 지시처럼 보이면 안 된다.
- primary blue는 action과 선택 상태의 신호로만 쓴다.
- `system` appearance는 별도 light/dark 값으로 복사해 저장하지 않고 OS appearance를 따르는 override 해제 상태로 유지한다. Native navigation, modal, form sheet의 uncovered area까지 같은 semantic background를 명시한다.
- 복구 UI는 앱을 가리는 장기 blank 화면 대신 themed loading shell, compact Home banner, 단일 retry action을 사용한다. 시작 shell은 배경과 브랜드를 바로 그리고 10초에 오래 걸린다는 문구와 다시 시도를 보인다. 데이터 삭제, 저장소 초기화, 자동 로그아웃을 복구 action으로 제시하지 않는다.
- `success`, `warning` 같은 별도 강조 색을 브랜드 색처럼 쓰지 않는다.
- 큰 graph와 큰 숫자를 한 화면에 여러 개 동시에 두지 않는다.
- safety 관련 copy는 항상 `review`, `reminder`, `non-certified assistant` 범위로 제한한다.
- v1 safety stop 권장은 보조 caution tone으로 표시하고, mandatory/decompression stop 같은 future 필수 상태와 같은 색상이나 위계로 표시하지 않는다.
- 모바일 `StatusPill`의 `warning` tone은 amber `--warning` token을 쓴다. 권장 스탑 미완료·일시정지, 동기화 부분 실패처럼 확인이 필요한 상태에만 쓰고, 오류·위험은 `danger`(destructive), 완료와 정상은 primary 또는 muted로 둔다. 권장 스탑 미완료를 빨강으로 표시하지 않는다.
- 되돌릴 수 없는 삭제는 시스템 Alert로 확인하고, 함께 지워지는 대상(Watch 원본, 다른 기기 사본)을 알린다. 수정 중인 편집 화면을 벗어날 때는 변경 폐기를 확인한다.
- 목록은 조회 실패(다시 시도), 검색·필터 결과 없음(검색어 지우기·모든 계획 보기), 처음부터 빈 상태를 서로 다른 문구와 action으로 구분한다.
- 그림자와 장식 그라데이션을 쓰지 않는다. 새 카드는 보더·그림자 없는 `rounded-2xl bg-card`이고, 누르는 행과 버튼은 `scale(0.95)`로 반응한다. 글꼴 굵기는 300/400/600/700만 쓰고 500(medium)은 쓰지 않는다(워치 글자는 400/600만, 아래 watchOS 번역).
- 워치 depth gauge의 그라데이션은 이 금지의 예외가 아니라 정보다. 색이 수심(m)에 고정돼 있어 현재 수심을 나타낸다(2026-10-23, D1). 워치 Wet Ready의 물빛 바탕은 소유자가 채택한 물속 대기 표시다(P4). 그 밖의 장식 그라데이션은 쓰지 않는다.

### 화면 문구

- 화면 문구는 다이버가 자연스럽게 읽는 말로 쓴다. 동기화 대상, outbox, claim, principal, import, provider, sample, runtime, session, guest 같은 개발자·시스템 용어는 화면과 접근성 문구에 내보내지 않는다. 오류 코드나 원본 오류 문자열도 화면에 그리지 않는다.
- 개념 하나에는 용어 하나만 쓴다. 기준 용어는 다이빙 기록(기록)/Dive log, 다이빙/Dive, 다이빙 시간/Dive time, 다이빙 포인트/Dive site, 다이빙 종류/Dive type, 수심 그래프/Depth chart, 워치 기록 가져오기/Get watch logs, 다시 보내기/Send again, iPhone에 저장됨/Saved on iPhone, 로그인 전 기록/Records made before sign-in, 계정으로 옮기기/Move to account, 기록 백업/Backup, 이 기기에만 저장, 수중 상태/Water conditions, 호흡 기체/Breathing gas, 훈련 목표/Training goal, 로그인/Sign in, 권장 스탑/Recommended stop, 스탑 구간/Stop zone이다. 워치에서는 저장한 기록/Saved logs, 워치에 저장됨/Saved on Watch, 계획 최대 수심/Planned max depth, 스탑 구간 시간/Time in stop zone을 더 쓴다(아래 워치 문구 결정).
- 스쿠버 압력은 탱크 압력/Tank pressure, 시작 압력/Start pressure, 종료 압력/End pressure다. 시작 값에 `잔압`을 쓰지 않는다. 계획의 예상 압력은 `탱크 압력 메모` 아래에 두고 탱크 압력 판단 기준이 아니라고 적는다.
- 워치 한국어는 동작 버튼/Action Button, 수중 잠금/Water Lock을 쓰고, 크라운은 문장에서 `디지털 크라운`, 짧은 chip에서 `크라운 ▸`로 쓴다. 한국어 값에서 `Divenary` 뒤 조사 앞에는 단어 결합 문자 U+2060(word joiner)을 넣어 줄바꿈에서 이름과 조사가 떨어지지 않게 한다. 문구 자체는 바꾸지 않는다(D20). 한국어 권장 스탑은 `스탑`으로 쓰고 `스톱`, `세이프티`를 쓰지 않는다.
- 문장은 대상 → 확인된 상태 → 필요한 행동 순서로 쓴다. 확인된 원인만 말하고, 실제로 가능한 복구 행동만 안내하며, 버튼은 실제 행동과 범위를 말한다. 저장 위치와 전송 방향(워치 → iPhone 저장과 계정 백업)을 섞지 않고, 전송 요청을 상대 기기의 수신 확인처럼 쓰지 않는다.
- 한국어는 `합니다/세요` 체로 쓰고 `해 주세요`처럼 띄어 쓴다. 영어는 sentence case다.
- 모르는 값은 `--`다. 단위를 가진 자리는 `-- m`, `-- bar`, `--분`처럼 단위를 남기고, 워치 실시간 값은 `--.- m`와 상태 chip을 쓴다. 0이나 정상 상태로 채우지 않는다.
- 문구를 줄이더라도 Demo/Test 표식, 지원 수심 밖 표식, 비인증 안내는 지우지 않는다.
- 실제 문구의 기준은 모바일 `apps/mobile/src/i18n/resources.ts`와 워치 `Localizable.xcstrings`다. 설계 문서에 따옴표로 적힌 화면 문구는 초안이다. `i18n.test.ts`와 `check-watch-ui-language.mjs`가 금지 용어, 권장 스탑 표기, 영어 단수·복수 key를 검사한다.

### 로딩과 피드백

naver-ad-bidder의 로딩 전략을 그대로 따른다. 시간 값은 `src/constants/async-feedback.ts`의 `ASYNC_FEEDBACK_TIMING`(indicator 1초, extended 4초, longRunning 10초)과 `CONTENT_LOADING_FEEDBACK`에만 두고, 화면은 `useLoadingFeedback`(`showIndicator`, `showExtendedFeedback`, `isLongRunning`)으로 읽는다. 컴포넌트마다 timer를 따로 두지 않는다.

- 1초 전에는 아무것도 보이지 않는다. 1-4초는 스켈레톤 또는 spinner, 4초부터는 멈춘 것처럼 보일 수 있는 곳에만 짧은 문구를 더하고, 10초부터는 재시도·복구 action이나 실제 진행률을 보인다. 스켈레톤이나 spinner를 끝없이 두지 않는다.
- 최소 표시 시간은 없다. 내용 스켈레톤과 앱 시작 shell 모두 데이터가 오면 바로 바뀐다.
- 구조를 예측할 수 있으면 스켈레톤, 아니면 spinner다. `SkeletonBlock`은 처음부터 최종 크기로 자리를 잡고 지연 동안 보이지 않다가 나타나며, 정적(pulse·shimmer 없음)이고 접근성에서 숨고 탭할 수 없다. 색은 `--skeleton` token이다. 호출자의 크기·radius class는 `cn`으로 합쳐 기본값을 대신한다.
- 스켈레톤은 실제 행·카드의 container, padding, 아이콘 자리, 줄 높이를 따른다. 제목, 헤더, 쓸 수 있는 control은 실제로 그리고 데이터 자리만 비운다. 목록은 3행, 페이지 꼬리는 2행, 카드는 1-2개다. 페이지 꼬리 스켈레톤은 클라우드 페이지처럼 실제로 비동기로 가져오는 동안에만 보이고, 메모리에서 자르는 페이지에는 표시하지 않는다.
- `useContentLoading`은 현재 범위에 유효한 내용이 아직 없는 읽기에만 쓴다. 이미 보이는 내용은 재조회 중에도 유지한다. 재조회 실패는 마지막 내용을 유지하고 작은 안내를 붙이며, 처음 불러오기 실패는 오류와 다시 시도다. 성공한 0건은 다음 행동이 있는 빈 상태이고, 로딩 중에 `0개` 같은 값을 보이지 않는다.
- 바쁜 영역은 0ms부터 `accessibilityState.busy`를 갖고, 보이는 spinner는 현재 언어의 라벨을 갖는다.
- `InstrumentButton`의 `pending`, grouped-list `Row`의 `pending`, `ListStateCard`의 `actionPending`은 0ms에 disabled·busy가 되어 중복 실행을 막고, 1초가 지나도 진행 중이면 고정된 자리에 spinner를 보인다. 버튼 문구는 바꾸지 않는다. 닫기, 취소, 관련 없는 action은 잠그지 않는다.
- 완료는 결과 화면이나 배너 한 번으로 알린다. 로컬 저장은 이 기기에 저장했다고 쓰고 계정 백업으로 표현하지 않는다.
- 결과 배너는 `useAppFeedback().notify(message, tone)` 하나로 띄운다. 보더·그림자 없는 `rounded-2xl` 배너가 tab bar 위에 뜨고, 4초 뒤 사라지며, VoiceOver에 한 번 알린다(iOS에는 polite live region이 없다). action이 없는 결과(저장함, 로그인함, 워치 기록 가져오기 결과)에만 쓴다.
- 워치 자동 가져오기 토스트는 `기록 보기` action이 있어 다이버가 닫을 때까지 남는다. 반전된 표면(`bg-foreground`)을 쓰고, 결과 배너는 그 위에 쌓인다.
- 워치는 저장 세션 목록을 동기로 읽어 스켈레톤이 없다. Home 센서 확인 중에는 placeholder 대신 실제 시작 카드를 비활성으로 그린다. 다이브 종료의 저장 중 화면은 즉시 보인다(저장이 main thread를 잡아 지연 timer가 동작할 수 없는 예외다). 실시간 수심·시간·상승 값에는 스켈레톤이나 redacted placeholder를 쓰지 않는다.

### 모바일 화면 규칙

모바일 화면은 다음 골격을 우선한다.

```txt
[screen padding]
  large title
  short subtitle

  primary summary group
    2-3 key facts
    one mini dive profile

  secondary grouped section
    compact label/value rows

  optional action
    at most one primary button

[tab bar]
```

화면별 역할은 다음처럼 좁힌다.

- Home: 큰 제목과 로그인 링크(Auth가 설정되어 있고 쓸 수 있는 로그인 방법이 있는 guest일 때만), 기록 개수 한 줄, 최근 기록 카드(mini profile 하나와 최대 수심·다이빙 시간, 데모·테스트와 지원 수심 밖 표식), 다가오는 계획이 있을 때만 `다음 다이빙` 행, 보조 빠른 action 한 줄(기록 작성, 계획 만들기), 날씨 카드 순서다. tab bar를 복제하는 큰 버튼은 두지 않는다. 최근 기록 카드는 처음 불러오기 스켈레톤, 처음 실패의 오류 카드와 다시 시도, 재조회 실패 안내, 빈 상태를 구분한다. 날씨 카드는 새로고침 중에도 값을 유지하고 버튼 자리에서만 1초 뒤 spinner를 보이며, 실패하면 마지막 값에 안내를 붙이고, 작은 `Open-Meteo 데이터` 출처를 적는다. 정보 tile은 neutral 배경이고, 당겨서 새로고침은 기록과 날씨를 함께 새로 고친다.
- Logbook: 목록 행은 보더 없는 `rounded-2xl bg-card px-4 py-3` 카드 하나다. 왼쪽 neutral 출처 아이콘, 첫 줄은 제목과 오른쪽 최대 수심, 둘째 줄은 `날짜 시간 · 다이빙 종류 · 다이빙 시간(47분)`이고, 태그 줄은 다이버가 직접 단 태그가 있을 때만, 표식 줄은 데모·테스트·이 기기에만 저장·지원 수심 밖이 있을 때만 보인다. 올해가 아니면 연도를 붙이고 `태그 없음`은 쓰지 않는다. 행마다 접근성 라벨 하나에 제목, 날짜, 표식, 수치를 담는다. 빈 상태는 직접 작성과 워치 기록을 모두 말하고 `기록 작성`, `워치 기록 가져오기` action을 둔다. 개수 줄은 로딩 중에도 자리를 지키고, 처음 불러오기 실패 때는 비운다.
- Planning: 헤더의 primary action은 `계획 만들기` 하나다. 다가오는 계획이 있을 때만 `다음 다이빙` 행을 두고, 4-way 필터와 필터 결과 없음 상태(`모든 계획 보기`)를 유지한다. 행 chip은 초안, 완료됨, 날짜 지남일 때만 muted로 붙는다. 상세는 언제·어디서, 다이빙, 압력 메모, 예상 조건, 사람·장비, 메모·목표, 준비 체크리스트 grouped section이며 계획값은 측정값이 아니라 계획으로 표시한다.
- Settings: 첫 group은 계정 행이다. guest는 `로그인`과 한 줄 이점, 로그인 상태는 `Apple로 로그인됨`/`Google로 로그인됨`(이 기기의 최근 provider 힌트, 없으면 `로그인됨`)과 계정 상세 chevron이다. Auth가 설정되지 않았거나 쓸 수 있는 로그인 방법이 없으면 `이 기기에만 저장`만 보인다. 알림은 목록 안 스위치, 테마·언어는 checkmark 하나로 표시하고, 정보 group에 앱 버전과 비인증 안내를 둔다. 행 아이콘은 neutral이다.
- Memory: share preview 하나만 시각적으로 살리고 future workflow나 analytics는 낮은 grouped rows로 축소한다.

편집기·상세 화면은 다음 패턴을 따른다.

- 편집기는 화면 전체의 root다. 위에 뒤로 버튼과 제목을 고정하고 저장은 아래 `StickyActionBar`에 고정한다. 저장 실패는 저장 버튼 바로 위에 보이고 VoiceOver에 알리며, 편집기를 열 때 이전 저장 오류는 보이지 않는다. 키보드가 열리면 저장 바와 초점을 받은 입력이 가려지지 않게 한다. 오류로 이동할 때는 고정 scroll 숫자가 아니라 측정한 anchor를 쓴다.
- 로그 편집기 section은 기본(날짜·시간, 다이빙 종류, 다이빙 포인트, 다이빙 시간, 최대 수심) → 후기(별점, 메모) → 세부 정보다. 세부 정보는 접혀 있다가 값이 있거나 첫 오류가 그 안에 있으면 펼쳐진다. 계획 편집기도 같은 구조(section, 고정 저장 바, 값 행)다.
- 숫자 입력은 label·값·chevron이 있는 값 행이고, 비어 있으면 `--:--`, `-- m`, `-- bar`다. 탭하면 bottom sheet에서 wheel 하나, 자주 쓰는 값 chip, 직접 입력, 지우기, Done을 고른다. 폼 안에 여러 wheel을 펼치지 않아 스크롤과 값 변경이 섞이지 않는다. 압력에는 chip을 두지 않아 어떤 숫자도 권장 잔량처럼 보이지 않는다.
- 날짜·시간은 Done이 있는 sheet picker다. 로그 편집기는 미래 시각을 고를 수 없고(`maximumDate`가 현재 시각), 계획 편집기에는 이 제한이 없다. 현재 언어 형식으로 보이고, 올해가 아니면 연도를 붙인다.
- 워치 기록의 시작 시각·다이빙 시간·최대 수심은 읽기 전용 행과 low-chroma `워치 측정값` chip으로 보인다. `직접 수정`을 누르면 입력이 열리고 `워치 값으로 되돌리기`로 돌아간다. 편집기 eyebrow는 출처에 따라 `워치 기록`/`직접 작성`이다.
- 사이트·버디는 이전 기록의 추천 chip을 보이고, 태그 입력은 쉼표와 return으로 확정한다.
- 상세는 큰 제목, 출처 chip 하나(+데모·테스트 chip), 날짜 → 요약 group(있는 값 2-3개와 수심 그래프 하나, 지원 수심 밖 review 표식) → 워치 기록 group(권장 스탑 pill, 프리다이빙 정보) → 빈 값은 숨긴 grouped 행 순서다. 형식은 수심 소수 첫째 자리, `3/5`, `200 → 50 bar`, `5점 중 n점`이다. 출처는 한 번만 보이고 직접 수정한 값에만 표시를 단다.
- 삭제와 로그아웃은 아래쪽 별도 group의 destructive 행(`Row` pending)이다. 진행 중에는 busy, 실패하면 inline 오류와 VoiceOver 알림이다. 확인 Alert는 유지한다.
- 상세·편집 route가 목록 로딩 전이면 `DetailSkeleton`(제목 줄, 요약 group, 행 3개)을 보이고, 목록 조회가 실패하면 오류와 다시 시도를 보인다. "화면을 찾을 수 없음"은 목록이 성공적으로 불러졌는데 항목이 없을 때만이다.

로그인과 계정 화면은 다음을 따른다.

- 로그인 sheet는 한 줄 이점(기록 백업, 다른 기기에서 보기)과 로그인 전 기록은 계정으로 옮길지 직접 고를 수 있다는 안내를 보인다.
- Apple과 Google 버튼은 한 쌍으로 그린다. 같은 50pt pill, 같은 라벨 크기(17/22), 같은 로고 자리를 쓰고, 극성은 각 브랜드 팔레트에서 같게 고른다. 밝은 sheet에서는 Apple 검정과 Google `#131314` 어두운 테마, 어두운 sheet에서는 Apple 흰색과 Google 밝은 테마다.
- 마지막으로 쓴 provider를 먼저 두고 버튼 모서리에 작은 최근 사용 표시를 단다. 2026-10-22 소유자 요청이 2026-07-17 로그인 개편의 "provider 목록 위 최근 사용 라벨" 결정을 대체한다.
- 로그인 오류는 오프라인, 다른 방법 시도, 서버 문제, 일반 오류로 나눠 VoiceOver에 알리고 원본 오류를 그리지 않는다. 버튼 spinner는 1초 지연을 따르고, 토큰 교환 중에는 4초에 확인 중 문구, 10초에 네트워크 확인 문구를 한 번씩 알린다. Apple·Google 화면이 열려 있는 동안에는 이 문구를 띄우지 않는다.
- 필수 동의 화면은 grouped list의 `모두 동의` 행, `[필수]` 문서 행(체크와 보기), 시행일, 아래 고정 동의 버튼(pending), header 취소 버튼이다.

구현할 때는 최상위 화면 padding을 공통 `Screen` 또는 native `contentContainerStyle`로 보장한다. `contentContainerClassName`만 믿고 화면 여백을 보장하지 않는다. 현재 Home, Planning, Settings는 React Native `ScrollView`의 `contentContainerClassName`을, Logbook은 고정 헤더 아래 `FlatList`의 `contentContainerClassName`을 쓰고 NativeWind가 이를 `contentContainerStyle`로 바꾼다. 다른 scroll container를 쓰면 이 변환이 되는지 먼저 확인한다. 화면이 edge에 붙어 보이는 회귀를 막기 위해 padding, section gap, row height는 공통 component에서 관리한다.

### 다이빙 계기 요소

다이빙 앱 고유성은 한 화면의 작은 instrument accent에서 나온다.

- `MiniDepthProfile`은 큰 막대 chart가 아니라 낮고 조용한 sparkline/profile이어야 한다.
- 수심, 경과 시간, rating 같은 수치는 필요한 곳에서만 크게 표시한다.
- temperature profile처럼 보조 정보는 primary profile보다 약한 색과 크기를 쓴다. 수온 그래프는 muted neutral 색이며, amber `warning` token은 권장 스탑 같은 확인 필요 상태에만 남긴다.
- assistant/status copy는 정보 row 안에서 짧게 표시하고, 큰 badge로 반복하지 않는다.
- Sync, demo, safety-stop 상태 chip은 내용의 존재를 알려주는 보조 표식이며 primary action처럼 보이면 안 된다.

### watchOS 번역

watchOS는 같은 제품 언어를 더 압축해서 쓴다. 현재 기준은 2026-10-23 워치 리디자인 'Plumb · 측심'이다. 설계 원본은 `docs/superpowers/specs/2026-10-23-watch-plumb-redesign/`(`DECISIONS.md` > `COPY-OVERRIDES.md` > `spec.md`, 가오리는 `LOGO.md`)이고, 아래 규칙은 구현 커밋 `b75ba8e`, `d4baae0`, `89e6b5c`, `0240824`, `b760320`에 반영된 내용이다. 리디자인은 표현·모션·문구만 바꿨다. 기록 판단(`RecordingPageModel`), 햅틱 5종, 1Hz 갱신, 종료 guard, 게이지 범위 공식, 비인증 경계는 그대로다.

#### 방향

- 기록 화면은 하나의 고정된 계기다. 상태 띠·게이지·안내 칩은 모든 기록 화면에서 같은 자리에 있고, 다이버가 화면을 넘기면 오른쪽 값 열만 바뀐다. 큰 숫자의 기준선도 화면마다 같다.
- 실시간 값은 제자리에서 바뀐다. 다이빙 상태가 바뀔 때만 움직임이 있고, 모르는 값은 회색 대시이며 지난 값을 현재 값처럼 그리지 않는다.
- 물 밖에서는 watchOS 기본 앱의 문법(시스템 행, 유리 툴바 원, 세로 페이지, symbol effect, 누름 scale 0.95)을 따른다. 직접 그리는 것은 다이빙에 필요한 게이지, 수심 그래프, 다이빙 종류 글리프뿐이다.
- 물속에서는 차분하고 땅에서는 축하한다. 기쁨을 주는 모션은 Home, 계획 선택, 저장 뒤 마무리에 둔다.
- 애플 앱과 닮는 것은 괜찮지만 특정 애플 앱 하나를 강하게 연상시키면 안 된다(2026-10-23 소유자 설명). 애플 '수심' 앱과 겹치는 `water.waves` 아이콘, 저장 순간의 "수심" 제목, 디지털 크라운과 "수심"을 짝지은 데모 문장은 쓰지 않는다. 일반 측정 라벨(`수심`, `최대 수심`, `수온`, `수심 정보 없음`)과 watchOS 기능 이름(`수중 잠금`, `자동 실행`, `동작 버튼`)은 그대로 쓴다.

#### 색과 역할

토큰은 `DiveWatchTheme`(`Views/DiveFormatters.swift`)에 있다. 한 색에는 한 의미만 준다: 검은 바탕, 흰 데이터, 회색 라벨, 남색 물기둥, 파란 조작, 앰버 권장 스탑.

- 바탕은 기록 화면과 Always-On을 포함한 모든 화면에서 검정이다. Wet Ready만 위에서 아래로 옅어지는 물빛 바탕(P4)을 내용 뒤에 깐다.
- 큰 숫자와 데이터는 흰색이다. 예전의 파란 큰 숫자는 쓰지 않는다. 라벨·단위·안내 문구는 ink2 `#AEAEB2`, 비인증 문장·`--`·`(n)` 번호 같은 작은 글씨는 ink3 `#8E8E93`이다.
- 파랑 `#2997FF`은 누르기와 선택(재생 원, 주 버튼, 선택된 Wet Ready 타일과 계획 행)과 프리다이빙 `다이빙 중` chip 글자에만 쓴다. 파랑 위 글자는 15pt/600 이상이다.
- 앰버 `#FFC74D`는 권장 스탑(라벨, 남은 시간, 스탑 구간 띠와 핀, 분 표시, 일시정지·완료 문구)에만 쓴다. 예외는 저장 기록의 `지원 수심 밖` 삼각형이다.
- 빨강 `#FF6B61`은 저장·전송·읽기·시작 실패와 전송 실패 아이콘에만 쓰고 기록 화면에는 없다. 기록 중 저장 재시도 표시도 회색이다(P7). 초록은 쓰지 않는다.
- 면은 플래터 `#262628`(누르는 카드·행·보조 버튼), chip `#1C1C1E`(상태·안내 chip과 빈 게이지 레일. 플래터보다 어두워 눌러 보이지 않는다), 표식 `#3A3A3C`(Demo/Test 표식, 글리프 원)이다. 테두리·그림자·blur는 없고 유리 재질은 시스템 툴바 원(뒤로, 데모 닫기, Wet Ready 홈)에만 쓴다.

#### 수심 게이지

`DepthGaugeRail`(폭 `layoutWidth = 46`)이 그리고 `RecordingGaugeGeometry`가 위치를 계산한다. 게이지는 다이빙을 판단하지 않고 보여 주기만 한다.

- 물 채움은 수심에 고정된 그라데이션이다. 0 m `#2F7FD1` → 10 m `#1F5A99` → 40 m `#0B2547`로 색이 미터에 묶여 있어 장식이 아니라 수심 정보다(D1). 채움은 실시간 수심이 있을 때만 0 m부터 현재 수심까지 보인다. 이 규칙이 "게이지 채움은 단색이고 그라데이션은 장식"이라는 이전 해석을 대체한다.
- 현재 수심은 검은 1pt 테두리가 있는 흰 지시선과 그 왼쪽 셰브론(`chevron.right`)이 함께 시곗바늘처럼 읽힌다. 새 sample마다 채움과 지시선은 0.3초 선형으로 따라가고 숫자는 즉시 바뀐다.
- 눈금 라벨은 1·2·5·10·20 m 단위로 네 개 이하이고, 지시선에서 8pt 안에 있는 라벨은 25%로 물러난다.
- 최대 수심 표시선(ghost)은 흰 50% 선과 오른쪽 노치이며 세부 화면에서 더 밝다. 뒤로 물러나지 않으며, 보이는 범위 밖이거나 지시선과 3pt 안이거나 Always-On이면 숨긴다. 프리다이빙은 따로 표시선을 두지 않는다.
- 프리다이빙 지난 다이빙 표시(tide marks, P5)는 하강 중이 아닐 때만 끝난 다이빙의 최대 수심에 최근 5개까지 짧은 눈금으로 보인다. 가장 최근 것은 80%, 이전 것은 35%이고 세부 화면에서는 100%/50%다.
- 권장 스탑 화면(보통 0–10 m)은 3–6 m 스탑 구간을 앰버 띠와 위아래 선으로, 5 m 목표를 작은 핀으로 그리고 물 채움을 50%로 낮춘다. 띠는 최소 18pt 높이다.
- 실시간 수심이 끊기면 채움·지시선·셰브론이 사라지고 표시선·라벨·tide marks는 남는다. 현재 위치에는 아무것도 그리지 않는다.
- 센서 허용 한계를 넘으면 범위는 한계에서 멈추고 채움이 한계까지 차며, 한계에 회색 상한선을 긋고 그 아래는 그리지 않는다. 지시선은 없고 `수심 측정 범위 밖` chip을 보인다. 전용 화면이 아니라 Live의 한 상태다.
- Always-On에서는 레일이 채움 없는 흰 외곽선이 되고 눈금선이 없어진다. 라벨과 지시선은 흐려지고(지시선 테두리 없음) 표시선과 tide marks는 숨으며, 스탑 구간은 앰버 위아래 선과 핀만 남는다.

#### 모양 문법

- 캡슐과 원은 누를 수 있다는 뜻이다(버튼, 툴바 원, 재생 원). 둥근 사각형은 정보다(상태·단계·Demo/Test 표식 chip 반경 6pt, 안내 chip 7pt). chip은 캡슐 모양이나 색 채움을 쓰지 않는다.
- 버튼은 전체 폭 캡슐이다. 주 버튼은 파랑 바탕에 흰 글자, 보조 버튼은 플래터 바탕에 흰 글자다(파란 글자는 링크처럼 읽힌다). 워치에는 파괴적 버튼 모양이 없다.
- 행과 카드는 watchOS 목록처럼 플래터 면에 놓이고 chevron과 테두리가 없다. 누르면 scale 0.95(동작 줄이기면 70%로 흐려짐)로 반응한다. 카드 안에 카드를 넣지 않는다.

#### 기록 화면 골격

실제·데모 기록 화면은 `RecordingInstrumentView` 하나의 골격을 공유한다. `VStack(spacing: 3)` → 상태 띠 → `HStack { 게이지 46pt; 값 열 }` → 안내 칩 구조와 `.padding(.bottom, 8).ignoresSafeArea(.container, edges: .bottom)`은 고정값이다.

- 상태 띠는 비어 있어도 자리를 지킨다. 위쪽 안전 영역과 상관없이 시계 아래 고정 위치(Ultra급 36pt, 42mm급 31pt)에 둔다. 상태 chip과 Demo/Test 표식이 왼쪽부터 놓이고, 프리다이빙 단계 chip(`수면 대기`, `다이빙 중`, `요약`)이 첫 chip이다. 같은 문구의 수심 상태 chip과 범위 밖 chip은 한 번만 그린다. 데모의 xmark 툴바 원이 있으면 chip은 그 옆에서 시작한다.
- 값 열의 칸 순서는 캡션 → 큰 숫자 → (권장 스탑 화면만) 상태 → 행 1 → 행 2 → 아래 칸이다. 캡션 칸은 비어도 자리를 지켜 큰 숫자의 기준선이 화면마다 같다. 큰 숫자와 단위는 따로 된 Text이고 같은 기준선에 놓이며 숫자는 rounded·고정폭이다.
- 보조 값은 한 줄에 하나씩 쌓고, 이름과 값이 한 줄에 안 들어갈 때만(`직전 다이빙 시간`, 프리다이빙 세부의 `직전 다이빙`) 이름 아래에 값을 둬 `2.1 m/min` 같은 값이 쪼개지지 않게 한다. 각 값 행은 VoiceOver 요소 하나(`라벨, 값`)이고 모르는 값은 `정보 없음`으로 읽는다(D20).
- 아래 칸은 계기 아래쪽에 붙어 있다. 물 밖(`notSubmerged`)이면 수중 잠금 줄 `수중 잠금 해제 시 기록 종료`가 여기에 보여, 수면에 올라와도 게이지 크기가 바뀌지 않는다. 종료 화면에서는 동작 버튼 힌트가 있는 기기에서만 이 줄을 유지한다. 동작 버튼도 수면에서 기록을 끝내는 방법이기 때문이다. 동작 버튼 힌트가 없는 기기의 종료 화면에서는 큰 안내가 이미 수중 잠금 해제를 말하므로 이 줄을 숨긴다(D20, `RecordingHint.showsWaterLockLine(on:)`). 저장이 불확실하면 같은 칸에 회색 `저장 재시도 대기`가 오고 글자와 간격이 한 단계 작아진다(tight).
- 크기 단계는 화면 폭 195pt 이상이 regular(Ultra급), 그보다 좁으면 compact이고, 저장 재시도 표시가 함께 있으면 tight다. 기록 화면 글자는 Dynamic Type을 따르지 않는 고정 크기이며 실제 표시 크기 11pt가 하한이다. 작은 화면에서는 문구를 줄이거나 중복 요소를 빼고, 글자를 하한 아래로 줄이지 않는다.
- 안내 칩은 아래 가운데에 있고 최대 폭은 184pt(compact 168pt)다. 페이지 점은 칩 안 왼쪽에 watchOS 세로 페이지처럼 세로로 쌓이고 현재 점만 흰색이다. 가로로 늘어놓던 이전 페이지 점은 대체됐다. 칩에는 탭 대상이 없다. 거부된 누르기는 2초 동안 칩 글자를 흰색으로 바꾼다. Always-On에서는 점을 숨기고 글자를 75%로 낮춘다.

#### 기록 화면 페이지와 안내

- 안내 칩은 다음 누르기가 무엇을 하는지 말한다. 물속은 `동작 버튼 ▸ 상세 1/2`, 물 밖 3분 전은 `기록 종료 가능까지 m:ss`, 종료 화면이 순환에 들어가면 Live에서 `동작 버튼 ▸ 상세 1/3`, 세부 화면에서 `동작 버튼 ▸ 종료 화면`이다. 거부된 누르기는 2초 동안 `지금은 기록을 끝낼 수 없음`을 보인다. 동작 버튼이 없을 것 같은 기기는 회전 방향을 밝힌 크라운 안내(`크라운 앞으로 ▸ 상세`, `크라운 뒤로 ▸ 실시간`)를 쓴다. 첫 하강 전에는 세부 화면에서 `동작 버튼 ▸ 종류 바꾸기 2/3`, 종류 바꾸기 화면에서 `동작 버튼 ▸ 스쿠버로 바꾸기`/`동작 버튼 ▸ 프리다이빙으로 바꾸기`를 보이고, 긴 문구는 `▸` 뒤에서 두 줄로 꺾인다. 누르기 안내는 항상 무엇을 누르는지 밝힌다. `눌러서`만 쓰면 화면 터치로 읽히고, Ultra에서 동작 버튼을 길게 누르면 사이렌이 울리기 때문이다. 바꾸기 화면 본문은 `스쿠버로 바꾸기`/`프리다이빙으로 바꾸기`와 `아직 잠수 전이라 새로 기록합니다.`이고, 실패하면 `다이빙 종류를 바꾸지 못했습니다.`를 알린다. 안내 칩, 화면 넘김, 바꾸기 화면, 종료 화면에는 탭 대상이 없다(2026-10-22 첫 구현의 터치 `바꾸기` 버튼은 이 규칙에 어긋나 지웠다).
- 종료 화면의 가장 큰 글자는 기록을 끝내고 저장하는 방법이고 `다이빙 시간`은 보조 값이다. 동작 버튼 힌트가 있으면 동작 버튼을 눌러 끝낸다는 안내와 칩 `동작 버튼 ▸ 기록 종료·저장`(점과 함께, D12)을, 없으면 `수중 잠금 해제 시 기록 종료·저장` 안내와 점만 있는 칩을 보인다(D20). 새 터치 대상은 없으며 입력 처리·햅틱·180초 이상과 현재 `notSubmerged` 조건은 그대로다.
- 데모 기록 화면은 화면을 넘기지 않고 크라운으로 수심을 바꾸며, 칩은 점 없이 `크라운 ▸ 수심 바꾸기`다. 툴바의 xmark 원으로 끝낼 수 있다.
- 기록 화면(실제·데모)에는 고정 비인증 표식을 두지 않는다. 2026-10-22 소유자 결정으로 예전 `기록용 · 인증 장비 아님` 표식을 뺐고 2026-10-23 리디자인도 이 결정을 유지했다. 비인증 문장은 기록 화면 밖(아래 문구 결정의 C3 위치)에 두고, 권장 스탑은 계속 `권장 스탑`으로 표시해 인증된 판단이 아님을 드러낸다.
- 화면마다 큰 숫자는 하나다. 스쿠버 Live·세부와 프리다이빙 하강 중 화면에서는 실시간 수심이 live일 때만 수심이고 그 밖에는 경과 시간이며, 권장 스탑은 남은 스탑 시간, 프리다이빙 수면 화면은 기록 시간이나 수면 휴식 시간, 프리다이빙 세부 화면은 다이빙 횟수다. 모든 기록 화면은 게이지, 수심 상태 chip과 Demo/Test 표식, 지원 수심 밖 경고를 유지한다.
- 세부 화면은 이미 publish된 값만, 보조 값은 두 개까지 쓴다. 스쿠버는 최대 수심과 수온, 프리다이빙은 다이빙 횟수(큰 값), 직전 다이빙(시간·수심), 최장 다이빙이다. 평균 수심과 상승 참고값은 넣지 않는다.
- 게이지 범위는 다이빙을 따라간다. Live·세부·프리다이빙·종료 화면은 30 m에서 시작해 최대 수심이 넘을 때 10 m씩 넓어지고 다이빙 중에는 줄지 않는다. 권장 스탑 화면은 스탑 구간이 크게 보이도록 보통 0–10 m이고, 30 m에서 10 m로 바뀔 때 0.6초 동안 한 번 보간한다(P3). 알려진 센서 허용 최대 수심은 상한이라 눈금·현재 수심 표식·스탑 구간을 그 너머로 그리지 않는다. 최소 표시 폭은 1m다. 2026-10-22 가독성 작업에서 허용 최대 수심(Ultra 40 m)에 범위를 고정했던 규칙은 소유자 요청으로 이 가변 범위가 대체한다.
- 권장 스탑은 진행·일시정지·미완료 모두 앰버와 `권장 스탑` 문구를 쓴다. 캡션 옆 세 칸의 분 표시(P2)가 지난 분만 채워지고 1분에 한 번 바뀐다. 일시정지는 색만이 아니라 `타이머 일시정지` 문구로도 구별하고 남은 시간이 흐려진다. 실시간 완료는 앰버를 유지하며 체크 표시와 `권장 스탑 완료`로 구분하고 튀지 않는다. 보조 값은 `수심`과 `다이빙 시간`이다. 저장된 기록의 완료 표식은 보조 회색이다. 실시간 수심이 현재 값이 아니면 숫자 대신 `--.- m`와 짧은 상태 chip을 보인다.
- Always-On(`isLuminanceReduced`)에서는 화면이 Live로 돌아가고 숫자는 흰색(권장 스탑 남은 시간 포함), 단위는 ink3, 게이지는 외곽선이다. 수심·시간 밖의 보조 숫자는 자리를 남긴 채 숨긴다. 권장 스탑 라벨과 일시정지·완료 문구, `수심`·`다이빙 시간`, 수심 상태 chip, Demo/Test 표식은 숨기지 않는다. 분 표시는 정지된 흐린 상태로 남는다.

#### 모션

`DiveMotion`(`Views/DiveDesignSystem.swift`)이 동작 줄이기와 Always-On을 받아 애니메이션을 고른다.

- 다이버가 동작 버튼이나 크라운으로 넘긴 화면 변화만 움직인다. 값 열만 6pt 위로 올라오며 바뀌고(0.35초, 부드럽게, 오버슈트 없음) 크라운을 뒤로 돌리면 반대로 움직인다. 다이버 조작 여부는 `RecordingPageChangeReason.isUserInitiated`로 구분한다.
- 자동 변화는 투명도로만 바뀐다. 10초 무입력 Live 복귀, 프리다이빙 단계 변화, 권장 스탑 시작, 수심 신호 변화 같은 자동 화면 전환(0.45초 크로스페이드), chip 등장·변경, 권장 스탑 완료 표시, 큰 숫자 종류 변경, 수중 잠금 줄, 새 tide mark가 여기에 속하며 확대·축소도 쓰지 않는다.
- 유일한 자동 이동 예외는 권장 스탑 범위 전환(30 → 10 m)이다(P3, D18). 0.6초 동안 한 번 보간하고 오버슈트가 없다.
- 숫자는 굴리지 않는다. 수심, 시간, 스탑 남은 시간, 수면 휴식, 프리다이빙 횟수는 `.contentTransition(.identity)`로 즉시 바뀌고, 요약 값도 세어 올라가지 않는다.
- 기록이 시작되면 게이지 레일이 위에서 아래로 자라고 값이 나타난다.
- 튐·오버슈트는 물 밖에서만 쓴다(계획 체크, 요약의 저장 체크). Wet Ready는 물속일 수 있어 선택 채움이 튐 없이 미끄러지고 글리프도 튀지 않는다.
- 동작 줄이기(`accessibilityReduceMotion`)면 모든 이동·확대가 0.2초 투명도 변화가 되고, 게이지는 sample마다 바로 옮겨 가며, 저장 뒤 마무리는 로고 없이 페이드만 남는다.
- Always-On이면 애니메이션이 없다. 진입·해제 때만 투명도와 색이 0.3초 정착하고 아무것도 움직이지 않는다.
- 모션은 햅틱을 부르지 않고 안전 상태나 권장 스탑 완료를 알리는 신호로 쓰지 않는다. 경계는 [안전 규칙](../domains/safety-rules.md)을 따른다.
- 물 밖 모션: Home은 실행 후 처음 나타날 때만 카드와 행이 40 ms 간격으로 떠오르고(다른 화면에서 돌아올 때는 반복하지 않음), 센서 확인이 끝나면 시작 카드가 밝아지고 재생 원이 파랗게 바뀌며, 시작 카드를 누르면 기록 시작과 함께 재생 원 둘레에 고리가 한 번 그려진다. 저장 기록 그래프는 기록마다 처음 보일 때 한 번 그려진다. 수중 조작 안내 그림은 페이지가 보일 때 한 번 움직인다.
- 저장 뒤 마무리는 실제 저장이 끝나고 요약이 처음 보일 때만 재생한다(뒤로 돌아올 때는 아님). 체크가 한 번 튀고, 최대 수심과 시간이 80 ms 간격으로 떠오르며(처음부터 실제 값), 0.9초 동안 그래프 선이 그려지고 물이 차오르는 동안 실제 로고가 선 끝을 따라가고, 0.9초에 최대점이 나타난다. 탭이나 크라운 회전은 끝 상태로 건너뛴다. `saved` 햅틱은 coordinator가 울리며 애니메이션이 부르지 않는다.

#### 출발 전 화면

- Home은 큰 제목 `다이빙` 아래 프리다이빙·스쿠버 시작 카드 두 개(회색 원 안의 모노핀·탱크 글리프, 제목, 파란 재생 원, 최소 높이 64pt)를 둔다. 센서 확인 중과 수심 측정 미지원 기기에서는 placeholder나 빨간 카드 없이 실제 카드의 글리프와 제목을 흐리게 하고 재생 원을 회색으로 그린다. 미지원 기기 안내(`Depth-capable Apple Watch required`와 데모는 쓸 수 있다는 문장)는 경보가 아닌 조용한 안내로 시작 카드 아래에 둔다(P13). 그 아래 다이빙 계획 행, 최근 기록 카드, `저장한 기록`·`수중 조작`·`데모` 행, 맨 아래 실제 로고와 비인증 문장 순서다. 당겨서 새로고침은 유지한다.
- 최근 기록 카드는 누를 수 없다. 상대 날짜(올해가 아니면 연도), 최대 수심과 다이빙 시간, 작은 수심 그래프, 해당할 때만 표식 줄을 둔다. 다이빙 종류는 보이지 않고(D4), 전송 상태는 오른쪽 위 아이콘만 있으며 VoiceOver가 전체 문구를 읽는다.
- `수중 조작` 행은 자동 실행 상태를 보이고 안내 화면으로 들어간다. 데모 행은 반쯤 찬 수심 기둥 글리프와 `기록 없이 둘러보기`다.
- 수중 조작 안내는 시스템 세로 페이지 세 장(자동 실행, 디지털 크라운, 동작 버튼)이다. 페이지마다 같은 축척의 하드웨어 그림(시계 아래쪽에 물이 차오름, 크라운 둘레 호가 4분의 1 회전, 동작 버튼이 눌림)이 페이지가 보일 때 한 번 움직인다. 마지막 페이지에 비인증 문장을 둔다.
- 계획 목록은 Home에 펼치지 않고 다이빙 계획 화면 한 행으로 들어간다. 계획 행은 제목 / 글리프와 종류 / `계획 최대 수심`과 값 / 날짜를 각 줄에 둬 줄바꿈이 생기지 않게 한다(C11). 고르면 파란 채움과 체크가 한 번 튀고 화면이 닫힌다.
- Wet Ready는 물빛 바탕(P4) 위에, 왼쪽 위 유리 툴바 원(홈, P12, 접근성 `홈 화면으로`)과 같은 줄에 `기록 대기` chip, 시계 아래 실시간 수심을 기록 화면 상태 띠 자리에 둔다. 그래서 기록이 시작돼도 chip이 움직이지 않는다. 그 아래 다이빙 종류 타일 두 개(선택은 파란 채움, 터치 최소 44pt, 수중 잠금 뒤에는 크라운이 주 선택 수단)가 있고, 스크롤 아래에 `아직 기록을 시작하지 않았습니다.`, 시작 안내, 크라운 줄, 비인증 문장이 온다.
- Wet Ready 시작 안내는 자동 실행 상태와 동작 버튼 힌트에 따라 `자동 실행이 켜져 있어 기록이 자동으로 시작됩니다.`, `동작 버튼에 Divenary를 지정했다면 눌러서 기록을 시작하세요.`, `입수 전에 다이빙 화면에서 기록을 시작하세요.` 중 하나다. 상태를 모르거나, 자동 실행이 꺼져 있고 동작 버튼 힌트가 없으면 마지막 문구다.
- 동작 버튼 유무와 Divenary 지정 여부를 알려 주는 공개 API가 없으므로 동작 버튼 문구는 항상 조건형("동작 버튼에 Divenary를 지정했다면 …")이다.

#### 다이빙 뒤 화면과 저장 기록

- 저장 중 화면은 흰 spinner와 한 줄 문구를 즉시 보이고 숫자는 보이지 않는다. 종료 중에는 기록 계기를 30 %로 남기고 그 위에 흰 spinner와 `기록을 종료하고 있습니다.`를 페이드로 올린다. 계기는 자리를 움직이지 않고 어두워지기만 한다(RC-END, D20). 기록 없음 결과는 빈 수심 기둥 글리프, `물속 기록이 없습니다`, `기록된 값이 없어 저장하지 않았습니다.`, `완료`다(C14).
- 시작 오류와 데모 시작·정리 오류는 오류 아이콘, 제목, 설명, 캡슐 버튼이다. `(n)` 번호 안내는 플래터 배너로 튐 없이 올라와 화면 아래 둥근 모서리 안쪽에 4초 동안 머문다. 저장 실패는 출시 문구, 자동으로 숨지 않는 번호 있는 안내, `다시 저장`과 `홈 화면으로`, 그 아래 다음에 일어날 일 순서다.
- 저장 요약은 최대 수심과 다이빙 시간을 먼저 두고 상태는 한 곳에만 보인다(D11). 툴바 뒤로 원과 제목 `요약` 아래 최대 수심(가장 큰 흰 숫자) → 다이빙 시간(스쿠버 `다이빙 시간`, 프리다이빙 `총 기록 시간`) → 최대 수심 라벨이 붙은 그래프 → 체크와 `워치에 저장됨` 순서이고, 실제 기록에서 동작 버튼 힌트가 있으면 아래에 점 없는 칩 `동작 버튼 ▸ 다음 다이빙 시작`을 고정한다. 아래 칩은 항상 다음 동작 버튼 누르기가 하는 일을 말한다. 스크롤하면 전체 전송 문구 줄, 권장 스탑 요약(참고 문장 먼저, C6 행) 또는 프리다이빙 요약, 통계, iPhone 안내, 비인증 문장이 온다. 데모 요약은 섹션 제목 옆에 `데모` 표식을 단다. 수심 측정 횟수는 상세 화면에만 둔다.
- 저장 목록은 최신순 플래터 행이다. 날짜(전체 폭, 글자 크기에 따라 줄바꿈)와 오른쪽 전송 아이콘, `22.4 m · 42분` 같은 값, 작은 그래프, 회색 평문 다이빙 종류와 표식 순서다. 목록과 Home 최근 기록은 날짜·최대 수심·시간·전송 상태·표식을 하나의 VoiceOver 요약으로 읽고 수심 그래프는 범위만 읽는다. 첫 읽기 실패는 오류 블록과 그 바깥의 `다시 시도`만 보이고 행을 그리지 않는다(C10). 빈 목록은 회색 실제 로고와 `아직 저장한 기록이 없습니다`다. 목록 끝에 비인증 문장을 둔다. 스크롤 가장자리의 행은 살짝 작아지고 흐려진다.
- 저장 상세는 날짜를 제목으로 한 시스템 세로 페이지 세 장이다. 첫 장은 종류·Demo/Test 배지와 시간, 그 아래 전체 전송 문구, 실패면 C5 안내와 `다시 보내기`, 처음 열 때 그려지는 그래프, 최대 수심과 시간이다. 둘째 장은 통계이고 `평점` 별점은 `5점 중 n점`으로 읽는다. 셋째 장은 권장 스탑 기록(참고 문장 먼저, C6 행) 또는 프리다이빙 다이빙 목록, 조건, 메모, 비인증 문장이다. 화면보다 긴 페이지는 다음 페이지 전에 스크롤된다.
- 전송 상태는 무엇이 일어나는지로 표시한다. Home 최근 기록과 저장 목록은 아이콘만(`applewatch.and.arrow.forward`, `iphone.gen3`, `iphone.gen3.slash`) 두고 접근성 라벨이 전체 문구를 읽는다. 요약과 상세는 아이콘과 `iPhone 전송 대기`, `iPhone에 저장됨`, `iPhone 전송 실패`를 함께 보인다. 아이콘은 회색이고 실패만 빨강이다. 실패한 기록 상세에만 `다시 보내기`를 둔다. 지원 수심을 넘은 기록에는 `지원 수심 밖` 표식을 붙인다(catalog key는 `Waiting for iPhone`, `Saved on iPhone`, `Not sent to iPhone`, `Send Again`, `Outside watch support`).
- post-dive rating, effort, visibility처럼 1-5 정수 평가를 받는 값은 watch에서 긴 wheel picker보다 짧은 별점 row를 우선한다.
- Home·목록·상세·요약의 읽기 문구는 상대 글자 스타일 또는 `@ScaledMetric`으로 Dynamic Type을 따른다.

#### 로고와 글리프

- 앱 안의 가오리는 실제 앱 로고 윤곽(`LogoMark`, 원본 `LOGO.md`)뿐이다. Home 하단(ink3, 비인증 문장 위), 저장 뒤 마무리(흰색, 그래프 선을 따라감), 빈 저장 목록(ink3)에 쓴다. 손으로 그린 가오리는 쓰지 않는다.
- `water.waves` 아이콘은 쓰지 않는다. 그 자리(기록 없음 결과, 데모 행)는 Divenary 수심 기둥 글리프(`DepthColumnGlyph`, 빈 기둥과 반쯤 찬 기둥)다.
- 다이빙 종류 글리프는 프리다이빙 모노핀, 스쿠버 탱크다(`DiveModeGlyph`, spec §C21 경로 그대로). 2026-10-23의 다이버 그림 한 쌍 시도는 되돌렸다(D19). 다이빙 종류에 색을 묶지 않는다.

#### 워치 문구 결정 (2026-10-23, C1–C15)

- 개념 하나에 용어 하나다. 다이빙 종류는 `프리다이빙`/`스쿠버`이고 시작 카드도 `스쿠버`다(C1). `스쿠버 다이빙`이나 `프리` 같은 줄임은 쓰지 않는다(D4).
- 스쿠버의 경과 시간은 기록 화면 행, 권장 스탑 화면, 종료 화면, Always-On, 요약·상세 모두 `다이빙 시간`(Dive time)이다. 프리다이빙 한 번의 시간도 `다이빙 시간`이고 프리다이빙 세션 전체는 `총 기록 시간`, `직전 다이빙 시간`·`최장 다이빙`은 그대로다(C15). 이전 기록 화면의 `시간`·`기록 시간`과 스쿠버 저장 화면의 `총 기록 시간`은 대체됐다.
- 권장 스탑 기록은 `상태`, `스탑 구간 시간`, `목표 수심 / 스탑 구간`, `시작`·`완료 시각`이다. 완료한 스탑은 `상태`, `스탑 구간 시간`, `목표 수심 / 스탑 구간`이 각각 한 줄 전체를 쓰고 `시작` | `완료 시각`이 마지막 줄에 나란히 온다. 완료하지 않은 스탑만 `남은 시간`과 `스탑 구간 시간`을 한 줄에 나란히 둔다(C6, D20). `권장 사항`(권장 판단 주장처럼 읽힘)과 `완료 여부`(상태와 중복) 행은 없고, `남은 시간`은 완료하지 않았을 때만 보인다(C6). 참고 문장 `권장 스탑 참고 기록입니다. 안전 판단에 사용하지 마세요.`는 섹션 제목 바로 아래, 값보다 먼저 둔다(C12).
- 저장 기록은 `저장한 기록`이다(Home 행, 빈 상태 `아직 저장한 기록이 없습니다`, 읽기 실패 `저장한 기록을 읽지 못했습니다.`)(C10).
- 계획 행은 `계획 최대 수심`이다. `계획 수심`은 쓰지 않는다(C11).
- 비인증 문장은 `다이빙 기록·복기용입니다. 인증된 다이브 컴퓨터가 아닙니다.` 하나다(문장 경계에서 두 줄 가능). Home 하단, Wet Ready, 수중 조작 안내 마지막 페이지, 요약(스크롤 아래), 저장 목록 끝, 상세 마지막에 ink3 작은 글씨로 두고 같은 화면의 안내보다 크게 쓰지 않는다. 다른 변형 문장은 쓰지 않는다(C3).
- 저장 위치와 전송 방향을 나눈다. 요약의 저장 상태는 체크와 `워치에 저장됨`이고 전송은 따로 `iPhone 전송 대기` 줄이다(C4). `전송 대기`, `iPhone 저장`, `전송 실패` 같은 줄임은 쓰지 않는다(C2, D3).
- 상세의 전송 실패 안내는 `전송하지 못했습니다. 다시 보내 주세요.`와 ink3 `(n)`이고 버튼은 `다시 보내기`다(C5).
- 크라운 안내 페이지는 `기록 중에는 디지털 크라운을 돌려 화면을 오갈 수 있습니다. 종류 바꾸기와 기록 종료는 그 화면에서 동작 버튼을 눌러야 합니다.`와 `수면에서 수중 잠금을 해제하면 기록이 끝납니다.`다(C7).
- 데모는 Home 행 `데모`/`기록 없이 둘러보기`, 기록 화면 칩 `크라운 ▸ 수심 바꾸기`다(C13). 예전 `가상 수심`과 `디지털 크라운으로 수심 조절`은 대체됐다.
- 기록 없음 결과는 `물속 기록이 없습니다` / `기록된 값이 없어 저장하지 않았습니다.` / `완료`다(C14).
- 그대로 둔 문구: 실시간 `권장 스탑 완료`, `평점`과 별점, 저장 실패 문구, `타이머 일시정지`, `수심 측정 범위 밖`(C8, C9).
- 문구 키 정책: 고정 테스트와 문구 검사가 잡고 있는 카탈로그 키(영어 원문)는 유지하고 en/ko 값만 바꾼다(예: `Time`·`Log time` → `Dive time`/`다이빙 시간`, `Saved` → `Saved on Watch`/`워치에 저장됨`, `Simulated depth` → `Browse without recording`/`기록 없이 둘러보기`). 새 문구는 en/ko를 모두 넣는다.

#### 공통 경계

- 바탕은 black canvas이고 면은 작은 rounded tile 또는 row로 제한한다. iPhone의 흰 grouped list를 그대로 옮기지 않는다.
- 기록 중에는 한 화면에서 하나의 주요 metric만 강하게 보이게 한다. action은 watchOS control 크기(터치 최소 44pt)에 맞추되 한 화면에 많이 두지 않는다.
- safety stop, ascent, no-fly 관련 표현은 인증된 판단이 아니라 assistant/reminder 상태로만 둔다.
- 햅틱은 다이버가 한 조작의 확인에만 쓰고, 자동 화면 전환이나 센서·권장 스탑·상승 상태 변화에는 쓰지 않는다. view와 애니메이션은 햅틱을 직접 울리지 않는다. 자세한 경계는 [안전 규칙](../domains/safety-rules.md)을 따른다.
- 워치 글자는 400(regular)과 600(semibold)만 쓰고 300과 medium(500)은 쓰지 않는다. 게이지 셰브론 기호만 설계의 굵은 획에 맞추려고 가장 굵은 symbol weight로 그린다. `check-watch-ui-language.mjs`는 medium만 금지한다.

#### 검증하지 않은 것

- polish 리뷰 반영 커밋 `c57f311`(2026-10-23)의 시작 오류 배너 여백(`PostDiveLayout.failureBannerReserve`, 64pt), 종료 중 30 % 계기, 한 칸짜리 기록 행의 전체 폭은 빌드, XCTest, 문구 검사까지만 확인했다. 시뮬레이터 캡처는 하지 않았다.
- 이 문서 작성 시점(2026-10-23)에 리디자인 마지막 단계(Task 6)인 Ultra 3(49mm)·Series 11(42mm) 시뮬레이터와 캔버스 비교, 동작 줄이기·Always-On 시뮬레이터 확인, 상태 띠 고정 위치(36/31pt)와 툴바가 있는 데모 화면의 40/41/44/46mm 시뮬레이터 확인은 끝나지 않았다(D20).
- 실기기에서만 확인할 수 있는 것: 41/42mm에서 한글 폭(종료 안내, 안내 칩 줄), 실제 sample 주기에서 게이지가 따라가는 느낌, 초록 물·밤·눈부심 속 남색 채움과 흰 지시선 가독성, Always-On 전환과 실제 밝기, 41/42/46/49mm 배치, 수중 잠금 중 크라운과 동작 버튼 연결, watchOS 26/27의 Liquid Glass 렌더링. simulator, XCTest, build 성공은 이 행동의 증거가 아니며 [열린 질문](../questions/open-questions.md)에 남긴다.

### 접근성

- 탭과 선택 pill은 selected 상태를 노출하고, 목록 행은 button role을 갖는다.
- 아이콘만 있는 컨트롤과 별점·pill·chip은 44pt 터치 영역을 갖는다. 시각 크기를 유지해야 하면 `hitSlop`으로 넓힌다.
- 별점은 "5점 중 3점", 프로필 차트는 범위만 요약(`최대 수심 {{max}}`, `수온 {{min}}–{{max}}`)하고 샘플 수는 읽지 않으며, number wheel은 VoiceOver 증감 동작을 제공한다. 상세 화면의 뒤로 버튼은 모두 "뒤로"로 읽힌다.
- 목록 행과 Home 최근 기록 카드는 접근성 라벨 하나에 제목, 날짜, 데모·테스트·지원 수심 밖 표식, 수치를 담는다. 시각 badge가 접근성에서 숨어도 표식이 들리게 한다.
- 저장·삭제 실패, 로그인 오류, 진행 문구, 막힌 계획 확정 같은 알림은 `AccessibilityInfo.announceForAccessibility`로 한 번씩 알린다.
- 텍스트 입력은 보이는 라벨을 접근성 라벨로 넘겨 영어 기본값("Input Field")으로 읽히지 않게 한다. 2026-10-22 기준 로그 편집기, 검색창, 계획 편집기의 텍스트 입력(계획 제목, 다이빙 포인트, 목표, 훈련 목표)에 적용됐다. 버디·장비·태그 입력은 아직 보이는 라벨 대신 placeholder `쉼표로 구분`으로 읽힌다.
- Watch metric card와 summary row는 제목과 값을 하나의 요소로 읽는다.
- 폼 검증 메시지는 검증 시점의 언어로 만들고, 한국어는 라벨 받침에 맞춰 을/를·은/는을 고른다.

### 회귀 방지

앞으로 UI를 바꿀 때는 다음 징후가 보이면 이 문서를 다시 참조한다.

- 화면 좌우가 0 padding처럼 보인다.
- 큰 card, 큰 chart, 큰 action button이 한 화면에 모두 있다.
- 같은 session 정보가 여러 card에서 반복된다.
- status pill이 screen title처럼 보인다.
- status chip이 primary button이나 filled action처럼 보인다.
- watchOS 화면이 iPhone grouped list를 축소한 것처럼 보인다.
- watchOS recording 화면이 depth gauge 없이 여러 metric card로만 구성된다.
- 다이빙 안전 기능처럼 읽히는 copy가 생긴다.
- 재조회가 이미 보이는 내용을 스켈레톤으로 덮거나, 1초 전에 spinner가 깜빡인다.
- 화면에 동기화, 세션, 샘플, guest, import 같은 개발자 용어나 원본 오류가 보이거나, 같은 개념이 화면마다 다른 이름으로 불린다.
- 워치 자동 화면 전환에서 햅틱이 울린다.
- 워치 큰 숫자가 파랗거나, 기록 화면에 빨강·초록이 보이거나, 앰버가 권장 스탑 밖에서 쓰인다(저장 기록의 `지원 수심 밖` 삼각형 제외).
- 워치 기록 화면의 자동 변화가 움직이거나 튀고(권장 스탑 범위 전환 보간 제외), 숫자가 굴러가거나 세어 올라간다.
- 워치 chip이 캡슐이나 색 채움이 되어 버튼처럼 보인다.
- 워치에 `water.waves` 아이콘이나 손으로 그린 가오리가 보이거나, 스쿠버 경과 시간이 `시간`/`기록 시간`처럼 `다이빙 시간` 밖의 이름으로 불린다.
